NanoLoop

A GPT-2-sized language model that thinks in depth. A small, weight-shared transformer core is looped a variable number of times per token, so the same 61M block parameters can act like a 28-layer network, and more loops at inference buy more latent compute. Stage 2 adds continuous "neuralese" thoughts on top.

Inside every attention layer

Gated attention block, in execution order

  1. 1 · projectFused QKV, 6 heads × 128. GQA-ready via n_kv_head.
  2. 2 · QK-normParameter-free RMSNorm on q and k, softmax scale 0.12.
  3. 3 · partial RoPERotate 64 of 128 dims (base 10k). The other half are position-free content channels.
  4. 4 · value pathsV += λ·value-embed(token); V = a·V + b·V₁ (value residual from layer 1).
  5. 5 · attendSDPA / FlashAttention, causal. Sliding window when the layer is L.
  6. 6 · XSAy −= tanh(α)·projv(y). Removes self-copy; α starts at 0 (no-op).
  7. 7 · output gatey ⊙ σ(Wgx), elementwise per head; kills attention sinks.
  8. 8 · out projZero-initialised, so every block starts as identity.
  9. MLPReLU², 4× width, zero-init output.
Inference & cache

KV cache for a looping model

  1. slotsEach core layer keeps one KV cache per loop slot (iteration i → slot i mod n).
  2. early exitA token that stops at loop e copies its final K/V into the slots it skipped (Huginn latest-state sharing). Later tokens always see a valid state.
  3. exit testKL between consecutive loops' next-token distributions < ε, or relative latent change < ε.
  4. DeltaNetHybrid preset: linear-attention layers keep a constant-size state plus a 3-tap conv buffer instead of K/V.
  5. verifiedIncremental decoding matches the full forward to 1e-6 for global, sliding-window and DeltaNet layers (tests).

Stage 2 · whynlp/gsm8k-aug

From written reasoning to continuous thought

stage 0 · 6 epPlain CoT SFTQ \n <<a=b>> <<c=d>> ### 42
stage 1 · 3 epStep 1 → 2 thoughtsQ ⟨bot⟩ ● ● ⟨eot⟩ <<c=d>> ### 42
stage 2 · 3 epSteps 1–2 → 4 thoughtsQ ⟨bot⟩ ● ● ● ● ⟨eot⟩ … ### 42
stage 3 · 3 epAll language droppedQ ⟨bot⟩ ●×6 ⟨eot⟩ ### 42

● = the model's own last hidden state, projected and fed back as the next input embedding. Each thought also runs r loops of the core, so the model can think in two directions: depth (loops per token) and length (number of thoughts). Caveat: 2512.21711 finds Coconut latents can act as placeholders, so perturbation tests come before any claim about reasoning.

Post-training · researched, not yet implemented

After pretraining: the planned pipeline

At about 200M parameters, general chat ability stays modest whatever you do; numbers become real on narrow, task-finetuned targets. RL makes tiny base models worse (TinyZero, L20-Edu-135M), so it comes only after task SFT, when pass@16 is above 30%. Keep the loop-count distribution identical in every stage, and re-measure accuracy against loop count after each one.

Training recipe · one 24 GB GPU
  1. dataFineWeb-Edu or ClimbMix (best measured by nanochat). Validate on FineWeb to compare with the 3.28 GPT-2 benchmark.
  2. batch2¹⁹ tokens/step = 8 × 2048 × 32 accumulation
  3. budget2.5B tokens by default (~4.8k steps). Raise toward 10B for the best model.
  4. precisionbf16 autocast, per-block torch.compile, fp32 chunked loss
  5. monitorval loss at r ∈ {1, 2, 4, 6, 12, 24}: the loop is working if loss keeps falling past r=6
